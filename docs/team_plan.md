## Mục tiêu dự án

### Mục tiêu chính

Phân tích dữ liệu âm nhạc toàn cầu từ Spotify (2009-2025) để:
1. Hiểu rõ xu hướng phát triển của âm nhạc qua thời gian
2. Phân tích các yếu tố ảnh hưởng đến độ phổ biến của bài hát và nghệ sĩ
3. Xây dựng mô hình dự đoán độ phổ biến của track/artist
4. Khám phá mối quan hệ giữa các thể loại âm nhạc và sự thành công
5. Cung cấp insights có giá trị cho ngành công nghiệp âm nhạc

### Kết quả mong đợi

- 1 Jupyter Notebook hoàn chỉnh với phân tích chi tiết
- 6 câu hỏi nghiên cứu được trả lời đầy đủ (bao gồm 1 ML model)
- Visualizations chất lượng cao và dễ hiểu
- Documentation đầy đủ và rõ ràng
- Source code clean, có comment và tuân thủ best practices

## Quy trình làm việc

### 1. Version Control (Git)

**Branch Strategy:**
- `main`: Production-ready code
- `develop`: Development branch
- `feature/[tên-feature]`: Feature branches

**Commit Convention:**
- `feat:` Thêm tính năng mới
- `fix:` Sửa lỗi
- `docs:` Cập nhật documentation
- `style:` Format code
- `refactor:` Refactor code
- `test:` Thêm/sửa tests
- `chore:` Maintenance tasks

**Example commits:**
```
feat: add exploratory data analysis for numerical columns
fix: correct missing value imputation logic
docs: update README with project structure
```

### 2. Code Review Process

1. Tạo Pull Request khi hoàn thành một phần công việc
2. Ít nhất 1 thành viên khác review code
3. Address comments và suggestions
4. Merge sau khi được approve

### 3. Communication

**Công cụ:**
- **GitHub Issues:** Track tasks và bugs
- **GitHub Projects:** Kanban board để theo dõi tiến độ
- **Zalo/Messenger:** Communication hàng ngày
- **Google Meet:** Weekly meetings

**Meetings:**
- **Weekly Sync:** Mỗi tuần 1 lần (45 phút)
  - Review tiến độ tuần trước
  - Discuss blockers
  - Plan công việc tuần tới
- **Ad-hoc meetings:** Khi cần thiết

### 4. Quality Standards

**Code Quality:**
- Follow PEP 8 style guide
- Meaningful variable names
- Comments cho logic phức tạp
- No hard-coded values
- Proper error handling

**Notebook Quality:**
- Clear markdown explanations
- Well-structured sections
- Clean visualizations
- Runs from top to bottom without errors

**Documentation:**
- Clear README
- Inline comments
- Docstrings for functions
